# 테마 레이더 — 주식 테마 분류 & 테마 뉴스속보

국내(코스피·코스닥) + 미국 증시 **42개 테마**를 사전(dictionary) 기반으로 분류하고,
뉴스를 자동으로 테마에 매핑해 "지금 어느 테마가 뜨는지"를 보여주는 앱.

## 구성

| 파일 | 역할 |
|---|---|
| `themes.json` | 테마 분류 사전 — 테마명·섹터·키워드(가중치)·구성종목(대장주/주도주/관련주) |
| `quotes.py` | 주요지수·환율 시세 수집 → 티커 데이터 생성 (`--diag` 로 소스 진단) |
| `collector.py` | 뉴스 수집 → 테마 분류 → 긴급도·심리 판정 → JSON/엑셀 출력 + 대시보드 갱신 |
| `notify.py` | 속보를 텔레그램·슬랙·윈도우 알림으로 발송 |
| `run.py` | `RUN.bat` 이 부르는 실행기 (수집 → 서버 → 브라우저 → 시세 감시) |
| `diagnose.py` | `DIAGNOSE.bat` 이 부르는 진단기 |
| `build_site.py` | GitHub Pages 용 `_site/` 생성 |
| `.github/workflows/update.yml` | 30분마다 자동 갱신 + 배포 |
| `dashboard.html` | 단일 파일 대시보드 (더블클릭으로 바로 열림, 서버 불필요) |
| `data/news_data.json` | 대시보드가 읽는 데이터 |
| `data/theme_report.xlsx` | 엑셀 리포트 3시트 (테마요약 / 뉴스 / 테마종목) |
| `data/quotes.json` | 티커가 읽는 시세 데이터 |
| `data/source_map.json` | 종목별로 '성공했던 시세 주소'를 기억해 두는 캐시 |
| `data/alerts.json` | 실제 발송된 알림 이력 (대시보드 상단에 표시) |
| `notify.json` | 알림 설정 (`ALERT_SETUP.bat` 또는 `notify.py --setup` 으로 생성) |

## PC 없이 돌리기 — GitHub 무료 서버

PC를 꺼도 30분마다 자동으로 갱신되고, 폰에서도 주소만 치면 보인다.
설정 방법은 **[SETUP_GITHUB.md](SETUP_GITHUB.md)** 에 단계별로 적어 두었다. 무료.

| | PC (`RUN.bat`) | GitHub |
|---|---|---|
| PC 전원 | 켜져 있어야 함 | 꺼도 됨 |
| 뉴스 | 돌릴 때마다 | 30분마다 자동 (평일 장중) |
| 시세 | 30초마다 | 30분마다 |
| 보는 곳 | 그 PC | 폰·회사PC 어디서나 |
| 알림 | 윈도우 알림 | 텔레그램 |

시세가 30초 → 30분으로 느려지는 게 유일한 손해다. 초 단위 시세가 필요하면 PC에서 돌리는 게 맞고,
둘을 같이 써도 서로 방해하지 않는다.

동작 구조: `.github/workflows/update.yml` 이 정해진 시각에 `collector.py` → `quotes.py` →
`notify.py` 를 돌리고, `build_site.py` 가 `_site/` 를 만들어 GitHub Pages 로 배포한다.
저장소에 결과를 커밋하지 않고 아티팩트로 바로 배포하므로 히스토리가 불어나지 않는다.
직전 실행 결과는 캐시로 넘겨받아, 이번 수집이 실패해도 화면이 비지 않는다.

**웹용 사본은 박아둔 데이터를 비운다** — `build_site.py` 가 `EMBEDDED_DATA` 를 `null` 로 만든다.
갱신이 실패했을 때 몇 시간 전 숫자를 아무 표시 없이 최신인 척 보여주는 것보다,
'데이터 없음'이 뜨는 편이 낫다.

## 실행

```bash
python3 collector.py                                  # 샘플 데이터 (오프라인 데모)
python3 collector.py --source rss                     # 실제 RSS 수집
python3 collector.py --source rss --hours 6 --xlsx    # 최근 6시간 + 엑셀
python3 collector.py --source file --input data/real_kr_news.txt --hours 48   # 텍스트 덤프 분류
python3 collector.py --market KR --min-score 4        # 국내만, 분류 기준 강화
```

> `--source rss` 는 본인 PC/사내망에서 실행해야 한다. 클라우드 작업 환경은 뉴스 사이트
> 아웃바운드가 막혀 있어 여기서는 `--source file` 로 검증했다.

### `--source file` — 망 제한 환경용
한 줄에 하나씩 `제목 ||| 출처 ||| 발행일시` (또는 `제목 ||| 발행일시`) 형식의 텍스트만 있으면
그대로 분류된다. `#` 로 시작하는 줄은 주석. 제목에 `美/뉴욕/나스닥/월가` 가 있으면 미국물로 자동 판정.

실행하면 `dashboard.html` 내부 데이터 블록이 자동 갱신된다. 파일을 브라우저로 열기만 하면 끝.
엑셀 출력은 `pip install openpyxl` 필요(그 외 의존성 없음, 표준 라이브러리만 사용).

## 시세 티커 (`quotes.py`)

```bash
python3 quotes.py                        # 샘플 시세 (오프라인 구조 검증)
python3 quotes.py --source auto          # 국내는 네이버, 해외는 야후 — 권장
python3 quotes.py --source auto --watch 30   # 30초마다 갱신, 대시보드는 자동 반영
python3 quotes.py --diag                 # 어느 시세 주소가 살아있는지 진단
```

**티커 구성** — 코스피 · 코스닥 · 코스피200 / S&P500 · 나스닥 · 다우 · 필라델피아반도체 ·
니케이 · 항셍 · 한국 ETF(EWY) / 원달러 · 달러인덱스 · WTI · 금 / 미10년물 · VIX · 비트코인.
상단 마퀴는 고정 종목만 돌고(hover 하면 멈춤), 전체는 `data/quotes.json` 에 다 들어간다.

**선물은 다루지 않는다** — 코스피200 주야간 선물, 해외 선물(ES/NQ) 모두 제외했다.
무료 소스가 계속 깨지는 데 비해 얻는 게 적었다. EWY(미국 상장 한국 ETF)는 선물이 아니라
ETF이고 야후에서 안정적으로 잡히므로, *간밤에 외국인이 한국을 어떻게 봤는지* 를 아침에
확인하는 용도로 남겼다.

**색상은 한국식** — 상승 빨강 / 하락 파랑. 색만으로 구분되지 않도록 ▲▼ 기호와 부호를 항상 함께 표기한다.

**세션 자동 판정 (KST)** — 동시호가 08:30~09:00 / 정규장 09:00~15:30 / 그 외 마감·휴장.

**시세 소스 — 후보 여러 개를 순서대로 시도한다**

무료 시세는 예고 없이 죽는다. 그래서 종목마다 후보 주소를 여러 개 등록해 두고 위에서부터
찔러, 처음 성공한 곳을 쓴다. 성공한 주소는 `data/source_map.json` 에 기억해 두었다가 다음
실행 때 맨 앞에서 시도하고, 그게 죽으면 자동으로 다음 후보로 넘어간다 — **코드를 고칠 필요가 없다.**

| 프로바이더 | 담당 | 비고 |
|---|---|---|
| `naver` | 국내 지수·환율 | 비공식 API 3종을 후보로 등록. Referer/Origin 헤더가 없으면 `409 Conflict` |
| `yahoo` | 해외 지수·ETF·원자재·금리·암호화폐 | 무키, 15~20분 지연 가능. query1/query2 두 도메인을 후보로 |

**값을 지어내지 않는다** — 수집에 실패한 종목은 `"ok": false` 로 남고 티커에서 `—` 로
비워 그린다. 시세가 없는 것과 0인 것은 다르다.

**시세가 비어 있을 때** — `PROBE.bat`(맥은 `python3 quotes.py --diag`)을 돌리면 위 후보 주소를
하나씩 찔러 어디가 살아있는지 표로 찍고 `PROBE_RESULT.txt` 로 저장한다. 진단기와 실제 수집기가
**같은 후보 목록**을 보므로, 진단에서 살아있다고 나온 주소는 실제로도 쓰인다.

## 분류 로직

1. **키워드 가중합** — 테마별 키워드에 1~3점 가중치. 종목명(별칭 포함) 직접 언급 시 대장주 +3.5 / 주도주·관련주 +3.0. 종목명은 한글 단어 경계를 검사해 `인텔`↔`인텔리안테크` 같은 부분일치 오탐을 막는다.
2. **시장 정합성** — 국내 기사가 미국 테마로 끌려가지 않도록 시장 불일치 시 점수 ×0.6. 단 **종목명이 직접 언급됐거나**(`루멘텀 실적` 기사에 `美` 표식이 없다고 미국 테마에서 밀어내면 손해다) **시장 무관 테마**(`cross_market: true` — ETF·제도·리포트·수급 등)면 감점하지 않는다.
3. **다중 라벨** — 임계점(`--min-score`, 기본 3.0) 이상인 테마를 점수순으로 최대 3개까지 부여. 1순위가 대표 테마.
4. **긴급도 3단계** — 속보/급등/상한가/사상최대 = 3(속보), 단독/수주/승인/신고가 = 2(중요), 그 외 = 1(일반).
5. **심리 판정** — 호재/악재 어휘 빈도 비교로 positive / negative / neutral.
6. **테마 열기(heat)** = 기사 수 + 속보 수 × 2 + 최신성 가중 × 1.5. 최근에 속보가 몰린 테마일수록 상단.

## 속보 푸시 알림 (`notify.py`)

긴급도 3(속보) 기사가 뜨면 **텔레그램 / 슬랙 / 윈도우 알림**으로 밀어준다. 대시보드를 안 보고
있어도 놓치지 않기 위한 것.

```bash
python3 notify.py --setup      # notify.json 만들기 (윈도우는 ALERT_SETUP.bat 더블클릭)
python3 notify.py --test       # 설정 확인용 테스트 발송
python3 notify.py --dry-run    # 무엇이 나갈지 화면으로만 확인
python3 collector.py --source rss --hours 2 --notify   # 수집과 동시에 발송
```

`notify.json` 이 있으면 `RUN.bat` / `UPDATE_NEWS.bat` / `start.sh` 가 자동으로 `--notify` 를 붙인다.
없으면 그냥 넘어가므로 알림을 안 쓰는 사람은 아무것도 안 해도 된다.

| 설정 | 뜻 |
|---|---|
| `min_urgency` | 몇 점 이상을 보낼지 (3=속보만, 2=중요 이상) |
| `themes` | 빈 배열이면 전체. `["kr-hbm","kr-defense"]` 처럼 관심 테마만 좁힐 수 있다 |
| `quiet_hours` | `[1, 7]` = 새벽 1~7시엔 발송 안 함. 끄려면 `null` |
| `max_per_run` | 한 번에 몰아 보내는 최대 건수 |

토큰은 환경변수 `TELEGRAM_TOKEN` / `TELEGRAM_CHAT_ID` / `SLACK_WEBHOOK` 로도 넣을 수 있고,
환경변수가 파일보다 우선한다.

**중복 발송 방지** — 보낸 기사는 제목 해시로 `data/notified.json` 에 기록한다. 10분마다 수집을
돌려도 같은 기사가 다시 나가지 않는다. 7일 지난 기록은 자동으로 지운다.

## 대시보드 기능

- 테마 열기 순위 막대 — 클릭하면 해당 테마 뉴스만 필터 + 구성종목 펼침
- 뉴스 피드 — 긴급도 배지, 호재/악재, 매칭 키워드, 관련 종목 칩
- 국내 / 미국 / 전체 탭, 속보만 보기, **미분류만 보기**(테마 신설 후보), 종목·키워드 검색
- 상단 타일에 **분류율 / 미분류 건수** — 사전이 얼마나 현실을 덮고 있는지 한눈에
- **발송된 속보 알림** 이력 — "내가 알림을 받았던가?" 를 화면에서 바로 확인
- 시세 수집 실패 시 티커에 `—` 와 실패 건수 표시 (조용히 옛날 값을 보여주지 않는다)
- 표 보기(복사·접근성용), 라이트/다크 모드

### 2차 보강 — 미분류 18건에서 읽은 것

미분류를 하나씩 읽어보니 **업종 테마가 아니라 '시장을 도는 이야기'가 빠져 있었다.** 유상증자·자사주,
목표주가 리포트, ETF·레버리지, 서학/중학개미, 예탁원·금융위 제도, 미국 소비주, 광통신…
업종 사전을 아무리 채워도 이건 안 잡힌다. 그래서 테마 8개를 새로 만들었다.

| 신규 테마 | 잡아낸 기사 예시 |
|---|---|
| 수급 이벤트 · 증자/자사주 | 엘앤씨바이오 유증 앞두고 지분 매각 / 하스 자사주 취득 |
| 증권가 리포트 · 목표주가 | "모건스탠리 원픽" / 제프리스 목표가 하향 |
| ETF · 패시브/인덱스 | 단일레버리지 모의거래 의무화 / ETF 괴리율 관리 강화 |
| 자본시장 제도 · 규제 | [단독] 예탁원 결제촉진대금 허용 검토 |
| 해외주식 · 서학/중학개미 | 중학개미 순매수 1위 '중지쉬촹' |
| 유통 · 소비재 | 신세계 실적 서프라이즈에도 37% 하락 |
| US Consumer · Retail | 웬디스 행동주의 공개매수설 |
| Optical Networking | 루멘텀·코히어런트 실적 |

이 중 다섯은 국내/미국 어느 쪽 기사에도 붙을 수 있어 `cross_market: true` 로 두고 시장 감점을 면제했다.
`[실적리뷰]루멘텀` 처럼 **미국 기업 기사인데 제목에 `美` 표식이 없는 경우**가 실제로 많아서,
종목명이 직접 언급되면 시장 감점을 걸지 않도록 규칙도 함께 바꿨다.

남은 미분류 2건은 둘 다 "인덱스펀드 50주년" 계열 낚시성 제목으로, 제목만으로는 무슨 얘긴지
사람도 알 수 없다. 여기서 억지로 0을 만들려 하면 오탐만 늘어난다.

**배운 것**: RSS는 제목만 오기 때문에 본문 있는 샘플 대비 신호가 절반 이하다. 국내 매체는
정식 종목명 대신 은어(`삼전닉스`)와 섹터 약칭(`전력기기株`)을 쓰고, 실제 뉴스량의 상당수는
개별 업종이 아니라 **실적·수급·증권가·제도 뉴스**다. 업종 사전을 아무리 채워도 여기서 막히므로,
'시장을 도는 이야기'를 테마로 세운 것이 정확도의 대부분을 결정했다.
**미분류는 실패가 아니라 테마 신설 후보 신호**다.

## 튜닝 포인트

- **테마 추가**: `themes.json`의 `themes` 배열에 항목 추가. `keywords`의 `w`는 1(약함)~3(강함).
- **오분류 잡기**: 특정 키워드가 과하게 잡히면 `w`를 낮추거나 `--min-score`를 올린다.
- **뉴스 소스 교체**: `collector.py` 상단 `RSS_SOURCES` 리스트만 수정. Google News 검색 수집은
  각 테마의 상위 3개 키워드를 자동 질의한다(`QUERY_PER_THEME`).
- **미분류 = 테마 신설 후보**: 대시보드에서 `미분류만` 을 눌러 쌓인 기사를 훑는 게 사전을 키우는
  가장 빠른 길이다. 분류율 타일이 떨어지면 시장에 새 이야기가 생겼다는 신호로 읽으면 된다.
- **정기 실행**:
  - 뉴스 `*/10 9-16 * * 1-5 cd /path && python3 collector.py --source rss --hours 2 --notify`
  - 시세 `python3 quotes.py --source auto --watch 30` 를 장중에 상시 띄워둔다
